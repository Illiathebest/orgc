# Контекст проєкту

Магістерська робота. Тема: «Метод компіляції декларативної моделі організації
в конфігурації мережевої інфраструктури з верифікацією інваріантів безпеки».
Дедлайн — початок грудня 2026. Мова спілкування — українська.

## Суть

Адміністратор описує **організацію** — сайти, мережеві сегменти, пристрої,
політики доступу — а не конфігурації окремих пристроїв. Компілятор `orgc`
перевіряє коректність опису формально **до** застосування і генерує
конфігурації різнорідного обладнання.

Наукова новизна — метод перетворення декларативної моделі в конфігурації
різнорідного обладнання з формальною перевіркою мережевих інваріантів.

`orgc` **нічого не застосовує** — тільки генерує текст. Застосування йде
наявним ланцюгом GitLab CI → Ansible.

## Дві команди

```
orgc verify organization.yml    # діагностики або OK; ненульовий код виходу при помилках
orgc render organization.yml    # конфігурації пристроїв + інвентарі
```

## Конвеєр

```
model → lower → IR → verify
                  └→ render → backends
```

IR не знає про вендорів. Бекенди підключаються через інтерфейс. Ядро про
конкретні платформи не знає нічого.

## Інваріанти верифікації — наукове ядро

| Код | Перевірка |
|---|---|
| E001 | Неперетин CIDR у межах сайту |
| E002 | Унікальність VLAN ID |
| E003 | Цілісність посилань: політика → мережа, пристрій → сайт |
| E004 | `mgmt_ip` належить мережі з роллю mgmt |
| E005 | Замкненість default-deny, немає правил any→any allow |
| E006 | **Досяжність управління** — існує дозволений шлях від вузла керування до mgmt-мережі кожного пристрою |
| E007 | Узгодженість адресного плану: шлюз поза DHCP-пулом тощо |
| E008 | Достатність ємності префікса |
| W001 | Guest-мережа без ізоляції |
| W002 | Можливість не підтримується цільовою платформою |
| W003 | Сайт профілю M без резервного каналу |

**E006 — головна перевірка роботи.** Реалізується як задача досяжності у
графі, індукованому множиною політик. Ansible і Terraform цей клас відмов не
ловлять у принципі — саме це й обґрунтовує новизну.

Емпіричне джерело E006 — реальний інцидент: заводський дефолт MikroTik
блокував керування з боку WAN-порту, доступ довелося відновлювати вручну
(`docs/reports/hw-handoff-2026-06-14.md`).

## Структура коду

Компілятор живе в цьому ж репозиторії, у теці `orgc/`. Схема, приклади,
CI та еталонний інвентар для golden-тестів уже тут — розділяти на два
репозиторії немає сенсу.

```
orgc/
  cmd/orgc/                 CLI, коди виходу
  internal/model/           структури, go:embed схеми, розбір YAML
  internal/ir/              проміжне представлення
  internal/lower/           model → IR
  internal/verify/          інваріанти E001-E008, W001-W003
  internal/diag/            діагностики: коди, шляхи, форматування
  internal/backend/         інтерфейс бекенда + реєстр
    routeros/               .rsc
    aristaeos/              .cfg
    ansible/                inventory + group_vars
    prometheus/             targets
    containerlab/           topology
  testdata/
    valid/ broken/ golden/
```

Шлях модуля — `greennet.ua/orgc`, узгоджено з `$id` наявної JSON Schema.

## Правила, які не обговорюються

**Детермінованість.** Однаковий вхід дає **побайтово** однаковий вихід. Це
предмет окремого експерименту, тому:

- жодних часових міток у згенерованих файлах
- жодного `map` без сортування ключів перед виводом
- жодної випадковості, жодних UUID на льоту
- закінчення рядків — LF

**Мінімум залежностей.** Стандартна бібліотека, де це розумно. Кожна
зовнішня залежність має бути обґрунтована — це аргумент у розділі про
відтворюваність.

**Мова.** Ідентифікатори й коментарі в коді — англійською. Тексти
діагностик для адміністратора — українською.

**Кожен інваріант має позитивний і негативний тест.** Негативний перевіряє,
що ловиться саме цей код помилки, а не будь-яка помилка.

## Що вже є і переходить у роботу

| Артефакт | Роль |
|---|---|
| `schema/organization.schema.json` | Frontend компілятора, `go:embed` |
| `examples/*.yml` | Основа для `testdata/valid` і `testdata/broken` |
| `ansible/inventories/staging/` | Еталон golden-тесту бекенда `ansible` |
| `.gitlab-ci.yml`, `ci/validate.gitlab-ci.yml` | Стадія `validate` перемикається на `orgc verify` |
| `runner-image/Dockerfile` | Потребує додавання Go toolchain |
| `docs/data-model.md` | Чернетка розділу 2 записки |
| `docs/adr/ADR-005-*` | Зафіксував, що JSON Schema не покриває семантику — звідси виросла тема |

## Схема потребує змін

Додати: `network.role`, `device.os_version`, `control_node`, `allow_overlap`,
`arista_eos` в enum типів пристроїв.

Прибрати: профіль `L` з enum, ролі `siem` та `identity` з `server.role`,
прапорці `identity_access` і `server_services` з `modules`.

## Викинуто — не пропонувати і не повертати

- Модуль Identity & Access (FreeIPA, Keycloak, Samba AD)
- Wazuh / SIEM
- Профіль L і міграція S→M→L
- HashiCorp Vault — лишається `ansible-vault`
- Модуль Server & Services
- Образи Cisco IOS — емуляція на Arista cEOS
- Terraform / OpenTofu — знято з роботи, модуль лишається як спадок
- Безперервне узгодження (reconcile) — тільки в розділ перспектив

`docs/CONCEPT.md` і `docs/ARCHITECTURE.md` застарілі, описують стару широку
платформу. Не спиратись на них.

## Стенд

| Вузол | Що це | Адреса |
|---|---|---|
| pve-a | Фізичний хост Proxmox VE 9.2, плата від ноута в коробці, 16 ГБ | 192.168.1.40 |
| ctrl-01 | VM на pve-a: GitLab CE + Runner + Registry, образ `iac-runner` | 192.168.1.50 |
| mon-01 | VM на pve-a: Prometheus, Alertmanager, Grafana, Loki | 192.168.1.51 |
| RB750 | MikroTik, RouterOS 6.48, користувач `ansible-ro` | 192.168.1.220 |
| pve-b | Nested Proxmox під containerlab — ще не піднятий | — |

`pve-*` — залізо з гіпервізором, решта — віртуалки на ньому.

Стенд потрібен лише для експерименту E4. Компілятор має збиратися й
тестуватися локально, без нього — це навмисний захист від блекаутів.

RouterOS **6.48**, не 7.x. Бекенд пишеться під синтаксис v6. Обмеження
платформи — готове джерело прикладів для попередження W002.

## Експерименти

| | Що міряємо |
|---|---|
| E1 | Масштабування: 10/50/200/1000 пристроїв, час компіляції й верифікації |
| E2 | Повнота виявлення дефектів: мутаційне тестування, ~50 мутацій на клас |
| E3 | Коефіцієнт абстракції: рядки моделі проти рядків згенерованих конфігів |
| E4 | Наскрізна валідність: конфіг застосовано на живий RB750 і containerlab, стан підтверджено NAPALM-геттерами |
| E5 | Локальність diff |

## Робота з репозиторієм

Зміни — лише через Merge Request у захищену `main`. Кожен MR проходить
lint → validate. Секрети — тільки `ansible-vault` або protected CI variables.

Нетривіальні технологічні рішення фіксуються як ADR у `docs/adr/`.
ADR-006 закрито як Rejected, номер вільний.
