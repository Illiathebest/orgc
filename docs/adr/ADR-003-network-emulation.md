# ADR-003: Емуляція мережевого обладнання

- **Статус:** Proposed
- **Дата:** 2026-06-07
- **Контекст:** Фізичного обладнання поки немає (пізніше з'явиться MikroTik). Потрібно емулювати Cisco IOS і RouterOS так, щоб (1) Ansible-ролі працювали без змін і на емуляторі, і на залізі, (2) топологія лабораторії сама була кодом у Git, (3) вкластися в RAM.

## Довідка по технологіях

- **GNS3 / EVE-NG** — найвідоміші емулятори для *ручних* мережевих лабораторій (навчання до CCNA/CCNP): малюєш топологію мишкою в GUI, вузли — повноцінні VM. Популярні, але топологія живе поза Git і їх практично неможливо запускати з CI.
- **containerlab** — сучасний стандарт саме в *NetDevOps*-спільноті (розробка Nokia, відкрита): топологія описується YAML-файлом, вузли запускаються як контейнери однією командою `clab deploy`. Створений для сценаріїв «лабораторія в Git + CI».
- **Cisco CML** — офіційний платний емулятор Cisco з легальними образами.
- **MikroTik CHR** (Cloud Hosted Router) — офіційний безкоштовний віртуальний RouterOS.

Це той випадок, де менш масова технологія *кратно* краща під задачу (принцип №1, виняток): GNS3/EVE-NG популярні для навчання вручну, але containerlab — галузевий вибір для автоматизації, і лише він дає «топологію як код».

## Варіанти

| Критерій | **A. containerlab** | B. GNS3 | C. EVE-NG CE | D. Cisco CML Personal |
|---|---|---|---|---|
| Топологія як код (YAML у Git, запуск у CI) | **так, нативно** | частково (API, GUI-центричний) | ні (веб-GUI) | частково (API) |
| Накладні витрати | мінімальні (Docker) | сервер + GUI | окрема VM 2+ ГБ | окрема VM 4+ ГБ |
| MikroTik | CHR через vrnetlab (~256 МБ/вузол) | CHR qemu | CHR qemu | ні |
| Cisco | IOL (~0.7 ГБ/вузол), cEOS-подібні | IOL/IOSv | IOL/IOSv | IOSv/CAT8kv (офіційно) |
| Легальність Cisco-образів | образи треба мати легально¹ | так само | так само | **офіційна ліцензія ~$199/рік** |
| Інтеграція з нашим CI | запуск стенда як job | складно | складно | можливо, важко |

¹ IOL/IOSv-образи поширюються лише з ліцензією CML або через сервісні контракти Cisco.

## Рішення (рекомендація)

**Варіант A: containerlab** на окремій VM (`net-emul`) у Proxmox. Топологія `lab/topology.clab.yml` живе в репозиторії — лабораторний стенд сам стає прикладом IaC, і CI може піднімати ефемерне мережеве середовище для інтеграційних тестів (сильний пункт роботи).

Образи:
- **MikroTik:** CHR — безкоштовний, офіційний; з появою фізичного MikroTik він додається в інвентар як ще один хост тієї ж групи — ролі не змінюються (це і буде демонстрація «емулятор → залізо»).
- **Cisco:** легальний шлях — образи IOL/IOSv з підпискою CML Personal (~$199/рік) або через ресурси GREENNET (партнерські контракти Cisco часто дають доступ до VIRL/CML-образів — варто перевірити на роботі). Якщо образів не буде — Cisco-частину демонструємо на borrowed-залізі з роботи, а в емуляції лишаємо лише MikroTik.

## Наслідки

- (+) ~0.25 ГБ на RouterOS-вузол, ~0.7 ГБ на IOL-вузол — топологія з 5–6 вузлів уміщається в ~3 ГБ.
- (+) Той самий Ansible-інвентар для емульованих і фізичних пристроїв (різниця — лише `ansible_host`).
- (−) CHR обмежений 1 Мбіт/с без ліцензії — для конфігураційних тестів неважливо.
- (−) Питання Cisco-образів треба закрити до M3 (перевірити доступ через GREENNET).

## Оновлення 2026-06-14 — з'явилося фізичне залізо (handoff)

Доступний реальний **MikroTik RB750** (RouterOS 6.48, 32 МБ RAM, 5×100 Мбіт, 1 ядро 400 МГц). Закриває половину відкритого питання — фізичний MikroTik уже є.

- **Роль:** ціль IaC + lab-роутер, **не дата-плейн** (100 Мбіт/32 МБ слабкі для трафіку, але для config-mgmt швидкість неважлива). Реальне залізо підсилює NetDevOps-розділ.
- **Версійне обмеження:** 32 МБ RAM = стеля **RouterOS v6** (v7 нежиттєздатна). Тулінг — `community.routeros` + `napalm-ros` під v6.49.x.
- **Цільова демо-топологія:** гібрид «реальний RB750 + containerlab-емуляція (CHR/IOL)» — однаковий інвентар, різниця лише в `ansible_host`.
- **Знахідка для продукту (безпека):** заводський MikroTik блокує керування з WAN-порту (firewall input + discovery лише на LAN) — жива ілюстрація ризику «замкнути себе зовні». Прямо обґрунтовує **Safe Mode / dry-run / rollback / ідемпотентність** у плейбуках. Ручний тимчасовий доступ (ether1 → list=LAN) згодом винести в IaC.
- Cisco-образи лишаються відкритими (GREENNET) до M3; MikroTik-частину можна демонструвати вже на залізі.

Деталі фізичної схеми та мережевий ADR-кандидат — у `docs/reports/hw-handoff-2026-06-14.md` §3–4.
