# E2: повнота виявлення дефектів

Для оцінки повноти використано мутаційне тестування. У коректні моделі вноситься рівно один дефект відомого класу. `orgc verify` має назвати клас цього дефекту. Пропуск дефекту чи каскад інших кодів поруч з очікуваним вважаються неточним результатом.

## Запуск

```
experiments/e2/run.sh
```

Експеримент запускається в образі `iac-runner` з кореня репозиторію. Результат зберігається в `results/`. Файл `e2.md` містить таблицю за класами й усі неточні випадки. У `mutants.json` для кожного мутанта записано клас, базу, що змінено, нові коди й результат.

Вибір мутантів детермінований (зерно 2). Прогін на Linux в образі й на Windows дає побайтово однаковий `mutants.json`.

## Методика

Базами є коректні моделі. До них належать приклади `s-profile`, `m-profile`, `lab`, моделі E4 `minimal`, `eos-gateway`, `capacity` і синтетичні моделі E1 на 50 і 200 пристроїв.

Оператори описано в `mutate.py`, по кілька на кожен із 16 класів. Кожен оператор перебирає всі придатні місця бази й повертає мутанти з одним дефектом свого класу:

| Клас | Оператори |
|---|---|
| E001 | нова мережа, що перетинається з мережею того самого чи іншого сайту |
| E002 | повторений VLAN у сайті, сервер з іменем пристрою, два канали з одним іменем, порт зʼєднання ще й access-порт, імʼя мережі з іншого сайту |
| E003 | правило, кінець зʼєднання, `vlans`, access-порти, вузол керування — на невідоме імʼя; канал на порту не-шлюзу |
| E004 | `mgmt_ip` пристрою в не-mgmt мережі свого сайту |
| E005 | правило `any → any`, правило `from: internet` |
| E006 | правило керування без порту платформи, правило керування видалено, активне зʼєднання без mgmt-мережі, mgmt-мережа без шлюзу |
| E007 | шлюз у пулі чи поза мережею, пул поза мережею, статична адреса в пулі, дві адреси збігаються, вузол керування поза мережею |
| E008 | /31, /32 зі шлюзом; шлюз і пул на одну адресу більші за префікс |
| E009 | видалено зʼєднання до листового пристрою; зʼєднання не несе мережу access-портів |
| E010 | зʼєднання, що замикає петлю; друге активне між парою; зʼєднання пристрою з самим собою |
| W001 | guest без `isolated`; правило з guest не до `internet` |
| W002 | версія ОС поза діапазоном бекенда; імʼя порту іншої платформи |
| W003 | сайт профілю M без резервного каналу |
| W004 | правило до mgmt-мережі не з мережі вузла керування |
| W005 | комутатор, що живить інші, отримує роль не вищого рівня, ніж у них |
| W006 | резервне зʼєднання без mgmt-мережі |

З кожного класу береться до 50 мутантів по черзі з усіх баз, щоб жодна база не домінувала. Для W003 таких мутантів 30, стільки є в базах сайтів профілю M із резервним каналом.

Результат мутанта визначається за діагностиками, яких немає в базі. Порівнюються повні тексти діагностик. Тому попередження, яке в мутанті замінилося іншим того самого коду, теж рахується:

| Результат | Що означає |
|---|---|
| точно | лише очікуваний код |
| разом з іншими | очікуваний код і ще інші — каскад, який ADR-008 забороняє |
| іншим кодом | очікуваного коду немає |
| пропущено | жодної нової діагностики |
| невалідні | мутант не проходить схему — дефект оператора, у частки не входить |

## Що знайшов E2

Перший прогін на `orgc` з `main` (`results/before-fixes/`) виявив кожен дефект (100 %). Однак 16 мутантів із 780 дали, крім очікуваного коду, ще й каскад:

- E006 разом з W006 (14). Це активне зʼєднання без mgmt-мережі в сайті з резервними зʼєднаннями. E006 указує на це зʼєднання, а W006 повторно звітував про нього як про перешкоду на резервному шляху інших пристроїв. Для виправлення W006 тепер пропускає зʼєднання, на якому E006 уже бачить відсутню mgmt-мережу;
- E002 разом з E006 (2). Це мережа з тим самим імʼям, що й mgmt-мережа іншого сайту. Правило керування посилається на мережу за іменем і розвʼязувалося на дубль, тому E006 повідомляв, що сайт відрізано. Для виправлення E006 більше не перевіряє керування мережею з повтореним іменем, бо цей дефект уже ловить E002.

Після виправлень 780 з 780 мутантів виявлено точно.

## Межі

Оператори описують дефекти тих класів, які перевіряє `verify`. E2 вимірює, наскільки повно й точно ловиться дефект відомого класу в будь-якому місці моделі. Дефекти класів, яких модель не описує, за побудовою сюди не входять.
