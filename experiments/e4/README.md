# E4: наскрізна перевірка

Конфігурацію, яку згенерував `orgc render`, застосовано на обладнанні. Після цього стан пристроїв прочитано через NAPALM і звірено з моделлю.

## Запуск в емуляції

Експеримент запускається на хості containerlab (`clab-01`, [ADR-010](../../docs/adr/ADR-010-emulation-stand.md)) з кореня репозиторію:

```
experiments/e4/run.sh experiments/e4/models/minimal.yml          # розгорнути, звірити, прибрати
experiments/e4/run.sh experiments/e4/models/minimal.yml --keep   # лишити топологію після звірки
```

Для запуску потрібні Docker, containerlab, образи `ceos:<версія>` і `vrnetlab/mikrotik_routeros:<версія>`, а також образ `iac-runner` (змінна `IAC_RUNNER_IMAGE`). Вихід зберігається в `experiments/e4/out/<модель>/`:

| Файл | Що в ньому |
|---|---|
| `render/` | вихід `orgc render`: конфігурації, інвентар, топологія |
| `lab/` | топологія, яку розгортає containerlab: копія з `render/` плюс міжсайтовий канал |
| `report.json` | очікуване й прочитане для кожного пристрою, розбіжності |
| `timing.txt` | час кроків: render, deploy, готовність вузлів, звірка |
| `deploy.log` | журнал containerlab |

Код виходу дорівнює 0, якщо розбіжностей немає, і 1, якщо вони є.

## Як це влаштовано

| Файл | Роль |
|---|---|
| `expected.py` | оракул: очікуваний стан кожного пристрою з YAML моделі, без `orgc` |
| `observe.py` | стан пристрою через NAPALM: `eos` по SSH, `ros` по API |
| `compare.py` | досяжність портів керування, звірка, звіт |
| `intersite.py` | міжсайтовий канал, який модель припускає, але не описує |
| `run.sh` | render → канал між сайтами → deploy → обліковий запис на cEOS → звірка → destroy |
| `failover.sh`, `failover.py` | перемикання STP: вимкнути активне зʼєднання й опитувати порти керування з вузла керування |
| `models/` | моделі, на яких проганяється перевірка, крім прикладів з `examples/` |
| `results/` | звіти й час прогонів, з яких складено таблицю |

Оракул не використовує ні `orgc`, ні його вихід. Він сам застосовує семантику з [`docs/data-model.md`](../../docs/data-model.md) і конвенцію портів ADR-009. Тому дефект у lowering чи бекенді проявляється як розбіжність. В очікуваний стан той самий дефект не копіюється.

Звірка запускається в мережевому просторі вузла, що замінює вузол керування (сервер моделі з адресою `control_node`). Пристрої читаються тим самим шляхом, яким до них ходить Ansible, через шлюз сайту і його правила. Мережею керування containerlab звірка не користується. Тому недоступний порт керування – це розбіжність, яку E006 мала б передбачити.

Звіряються:

- VLAN: номер і ім'я;
- адреси VLAN-інтерфейсів у мережах моделі;
- trunk-порти з дозволеними VLAN;
- access-порти з їхнім VLAN;
- досяжність порту керування платформи (RouterOS 8728, EOS 22) з вузла керування;
- повнота прийняття конфігурації. Кожен рядок `.cfg` має бути в running-config EOS. Відомі порти EOS показує іменами, тому обидві сторони нормалізуються однаково. Скрипт RouterOS має дійти до останньої команди, що вмикає VLAN-фільтрацію, а в журналі не має бути помилок скрипту. Цей пункт порівнюється з виходом `orgc`, з моделлю його не звіряють. Він ловить відкинуту команду чи обірваний `/import`, після яких решта параметрів може лишитися правильною.

Кожен із пунктів рахується як один параметр.

## Між сайтами

Модель не описує, як сайти дістаються один до одного. Вона вважає L3-шлюзи повнозв'язними (на стенді між ними тунель WireGuard). В емуляції такого зв'язку немає. RouterOS у vrnetlab стоїть за NAT QEMU, а маршрут за замовчуванням шлюзу веде в uplink із маскарадингом. Тунель замінює `intersite.py`. У копії топології він з'єднує шлюзи кожної пари сайтів на перших вільних портах. До копій їхніх стартових конфігурацій він дописує транзитну адресу `/30` з `10.99.2.0/24` і статичні маршрути до мереж інших сайтів. Вихід `orgc` при цьому не змінюється.

| Модель | Вузли | Що перевіряє |

| `examples/organization.s-profile.yml` | CHR + 3 cEOS + 2 сервери | ієрархія Access–Core |
| `models/eos-gateway.yml` | 2 cEOS + сервер | EOS як шлюз: SVI, DHCP-сервер, ACL з кількома портами, ізоляція гостьової мережі |

| `models/capacity.yml` | 2 CHR + 9 cEOS + 3 сервери | найбільша топологія на межі ємності стенда: три сайти, повна ієрархія, резервні зʼєднання на кожній платформі, EOS-шлюз у dc |

## Перемикання STP

Резервне зʼєднання (`standby: true`) STP тримає заблокованим, доки не відмовить активне зʼєднання циклу. Для перевірки на розгорнутій топології (`run.sh … --keep`) виконаємо:

```
WATCH=acc-01 experiments/e4/failover.sh hq-acc-01 ctrl-01 dist-01 Ethernet2 192.168.10.5:22
```

`failover.sh` вимикає інтерфейс cEOS на 40 с. Тим часом `failover.py` з мережевого простору вузла керування кожні 0,25 с пробує порти керування пристроїв за ним. В результаті для кожної цілі отримано сумарний і найдовший час недосяжності (`results/failover/`). `WATCH` показує ролі портів STP посеред відмови. Резервний порт має стати `root`/`forwarding`.

`incident/capacity-w006.yml` містить ту саму найбільшу топологію, але резервне зʼєднання acc-01 не несе mgmt-мережу. `orgc verify` видає попередження W006. На емуляції після відмови активного зʼєднання резервний порт переходить у `forwarding`, але mgmt-VLAN через нього не йде, і acc-01 недосяжний увесь час відмови.

## Живий RB750

Для перевірки використано модель `examples/organization.lab.yml` і вузол керування `ctrl-01` (`192.168.1.50`). Процедура складається з таких кроків:

1. На флеш RB750 кладуться `rb750.rsc` з виходу `orgc render` без змін і обгортка `e4-apply.rsc`. Обгортка виконує `:delay 15s`, потім `/import file-name=rb750.rsc`. Затримка потрібна, бо скрипт `run-after-reset` стартує раніше, ніж піднімаються інтерфейси.
2. Скидання робить людина у WinBox по MAC через `ether5`: `/system reset-configuration no-defaults=yes skip-backup=yes run-after-reset=e4-apply.rsc`. Після скидання IP-адреси немає, тому плейбук `apply_routeros` тут не підходить.
3. Облікові записи заводяться через API поза orgc. Модель їх не описує, а після скидання лишається лише `admin` без пароля.
4. На `ctrl-01` запускається `compare.py --render`.
5. Відкат виконується через `/system backup load` з копії, зробленої до експерименту, теж у WinBox по MAC.

`results/organization.lab/reachability.log` – це журнал досяжності API (8728) і SSH (22) з `ctrl-01`. Опитування йде щосекунди, час записано в UTC.

### Модель стенда і фізичне підключення

Модель `organization.lab.yml` описує RB750 як шлюз мережі `lan`, яка стоїть *за* ним. У моделі trunk іде на `ether2`–`ether4`, адреса `192.168.1.220` стоїть на `vlan1-lan`, а `ether1` є каналом до провайдера з DHCP-клієнтом. Фізично `lan` – це домашня мережа, підключена до `ether1`, а за RB750 нічого немає. Після застосування `192.168.1.220` опинилася на двох інтерфейсах: статично на `vlan1-lan` і від DHCP на `ether1`. Маршрут `192.168.1.0/24` став активним через обидва. Керування працювало, але через `ether1`. Модель описує для нього інший інтерфейс.

У цьому полягає межа методу. `orgc` перевіряє узгодженість моделі, а відповідність моделі кабелям він не перевіряє. Таку розбіжність здатна показати лише наскрізна перевірка на обладнанні, і в цьому випадку її показала вона.

## Інцидент E006

`incident/lab-e006.yml` – це модель стенда, у якій вузол керування стоїть в окремій мережі, а правило до мережі керування відкриває лише SSH. `orgc verify` відхиляє її з E006 («правило відкриває tcp/22, а керування пристроєм rb750 (mikrotik) іде через tcp/8728»), і `orgc render` нічого не генерує. З `ports: [22, 8728]` модель проходить.

На живому RB750 ту саму правку внесено вручну, в обхід orgc: у правилі керування порт 8728 замінено на 22. Сесія, через яку це зробили, ще встигла прочитати результат. Через 2 с нові API-з'єднання з `ctrl-01` перестали встановлюватися, а SSH лишився відкритим. Іншими словами, пристрій «доступний», але Ansible відрізаний. Повернути керування вдалося лише в обхід IP, через WinBox по MAC.

## Застосування на справжньому обладнанні

В емуляції конфігурацію застосовує containerlab (`startup-config`). На справжньому обладнанні її застосовують плейбуки з виходу `orgc render`. Для цього виконаємо:

```
cd ansible
ansible-playbook -i <вихід>/ansible/hosts.yml playbooks/apply_eos.yml -e orgc_out=<вихід>
ansible-playbook -i <вихід>/ansible/hosts.yml playbooks/apply_routeros.yml -e orgc_out=<вихід>
```
