# E4: наскрізна перевірка

Конфігурацію, яку згенерував `orgc render`, застосовано на обладнанні, стан прочитано NAPALM і звірено з моделлю.

## Запуск в емуляції

На хості containerlab (`clab-01`, [ADR-010](../../docs/adr/ADR-010-emulation-stand.md)), з кореня репозиторію:

```
experiments/e4/run.sh experiments/e4/models/minimal.yml          # розгорнути, звірити, прибрати
experiments/e4/run.sh experiments/e4/models/minimal.yml --keep   # лишити топологію після звірки
```

Потрібні Docker, containerlab, образи `ceos:<версія>` і `vrnetlab/mikrotik_routeros:<версія>` і образ `iac-runner` (змінна `IAC_RUNNER_IMAGE`). Вихід — `experiments/e4/out/<модель>/`:

| Файл | Що в ньому |
|---|---|
| `render/` | вихід `orgc render`: конфігурації, інвентар, топологія |
| `report.json` | очікуване й прочитане для кожного пристрою, розбіжності |
| `timing.txt` | час кроків: render, deploy, готовність вузлів, звірка |
| `deploy.log` | журнал containerlab |

Код виходу — 0, якщо розбіжностей немає, 1 — якщо є.

## Як це влаштовано

| Файл | Роль |
|---|---|
| `expected.py` | оракул: очікуваний стан кожного пристрою з YAML моделі, без `orgc` |
| `observe.py` | стан пристрою через NAPALM: `eos` по SSH, `ros` по API |
| `compare.py` | досяжність портів керування, звірка, звіт |
| `run.sh` | render → deploy → обліковий запис на cEOS → звірка → destroy |
| `models/` | моделі, на яких проганяється перевірка |

Оракул не використовує ні `orgc`, ні його вихід. Він сам застосовує семантику з [`docs/data-model.md`](../../docs/data-model.md) і конвенцію портів ADR-009. Дефект у lowering чи бекенді тоді видно як розбіжність, а не як копію того самого дефекту в очікуваному стані.

Звірка запускається в мережевому просторі вузла, що замінює вузол керування (сервер моделі з адресою `control_node`). Пристрої читаються тим самим шляхом, яким до них ходить Ansible: через шлюз сайту і його правила. Мережею керування containerlab звірка не користується. Тому недоступний порт керування — це розбіжність, яку E006 мала б передбачити.

Звіряються:

- VLAN: номер і ім'я;
- адреси VLAN-інтерфейсів у мережах моделі;
- trunk-порти з дозволеними VLAN;
- access-порти з їхнім VLAN;
- досяжність порту керування платформи (RouterOS — 8728, EOS — 22) з вузла керування.

Кожен із пунктів рахується як один параметр.

## Застосування на справжньому обладнанні

В емуляції конфігурацію застосовує containerlab (`startup-config`). На справжньому обладнанні її застосовують плейбуки з виходу `orgc render`:

```
cd ansible
ansible-playbook -i <вихід>/ansible/hosts.yml playbooks/apply_eos.yml -e orgc_out=<вихід>
ansible-playbook -i <вихід>/ansible/hosts.yml playbooks/apply_routeros.yml -e orgc_out=<вихід>
```
